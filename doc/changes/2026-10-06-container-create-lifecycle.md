# Fresh container creation extraction

Fresh creation after the existing-container flow now delegates through a
required synchronous application and native composition. The existing family
guard encloses namespace/collision refusal, ordered reporting and lazy run
arguments, separate source assertions, native creation, bind proof and handoff.
Public signatures, messages, stdio and errors remain unchanged. Outer
preparation, native proof helpers and shared finish retain their implementation.

Native creation, rejected-ID removal and absence inspection retain the captured
CLI. Status is checked before stdout; status zero ignores native error fields.
The first complete 64-hex token retains its case. Post-create source/proof
failure compensates only that exact ID, then separately proves absence using
the existing classifier. Missing IDs never authorize namespace cleanup. MCP,
SSH, Git and finish remain outside compensation, preserving late-failure
outcomes and current-runtime selection by existing collaborators.

Portable core/type/facade regressions exercise the actual boundary. Coordinator
verification for the source cutover recorded a successful full build, scoped
source lint and 37 regression files with 1814 passing tests, plus exact source
hashes and unchanged Docker bytes outside the creation tail/import. Those checks
are implementation evidence; independent review and final QA remain required.

Distribution smoke now includes the actual compiled application and synchronous
declarations in both extracted npm packages and materialized installs. It adds
ordered success, namespace/collision refusal, missing-ID preservation, all
nonverified proof variants, exact-ID compensation, unknown-absence cause and
late-failure preservation. Native subprocesses are fenced before composition and
Docker imports/construction; lazy native context callbacks must not run then.
Coordinator execution of these new distribution checks passed in both forms;
built CLI help/version/invalid-runtime probes returned the expected 0/0/1.
Independent review and final QA still determine candidate acceptance. No live
container is created or removed by the smoke.

Preparation, shared finish/handoff, setup/credentials and reliable native
outcomes remain separate migration work. Full M00–M14 acceptance and native
lanes are outstanding; this packet does not resolve M02c attestation.

## Known ceiling

Known ceiling: creation with an unknown outcome or no exact returned ID cannot
authorize cleanup — upgrade when a separate reconciliation policy is approved.

Known ceiling: native removal/inspection throws may obscure the primary
verification error — upgrade when compensation semantics changes are approved.

Known ceiling: portable tests and package smoke cannot establish native
Windows/macOS, PowerShell execution, Docker/Podman, rootless UID/SELinux or remote
creation/handoff/cleanup behavior — upgrade when the retained native acceptance
gates execute against the actual source and artifact hashes.
